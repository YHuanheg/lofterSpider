### 快速开始

**第一步：装依赖**（要求 Python 3.10+，推荐 3.12）

```bash
pip install -r requirements.txt
```

**第二步：填登录信息**（下面的「填写登录信息」章节有详细图文）

**第三步：跑起来**

| 方式 | 怎么启动 | 适合谁 |
| --- | --- | --- |
| **图形界面** | 双击 `run_gui.bat`，或者命令行 `python main.py` | 所有人，推荐 |
| 命令行 | `python main.py --task 任务id --set 参数=值` | 想写脚本 / 定时任务的人 |
| 老脚本 | `cd legacy && python l13_like_share_tag.py` | 想对照老行为的人 |

**界面里怎么用**：左边选任务 → 右边填参数 → 点「开始」→ 切到「运行日志」看进度 →
跑完点「打开输出文件夹」。中途需要确认时会弹窗，点「取消」可以随时中断。

**命令行怎么用**：

```bash
python main.py --list                          # 看有哪些任务
python main.py --show-config collection        # 看某个任务的参数和默认值
python main.py --login                         # 交互式填登录信息

# 下载一个合集（合集 ID 从 App 的分享链接里拿）
python main.py --task collection --set source=collection_id --set collection_id=20763900

# 保存一个 tag 下的内容
python main.py --task like_share_tag --set mode=tag --set url=https://www.lofter.com/tag/怪想售/total
```

命令行里 `--set` 用过的参数会**自动存下来**，下次不用再打一长串。

#### 下载 lofter 合集（连载整本）

界面任务：**下载 lofter 合集（连载整本）** ｜ 命令行 id：`collection`

网页端一直看不到合集内容（这是 lofter 的老毛病），这个任务把整个合集按章节顺序抓下来。

##### 怎么拿到合集 ID（推荐方式）

打开 lofter App → 进这个合集 → 右上角分享 → 复制链接，
链接里 `CollectionId` 后面那串数字就是合集 ID。填到「合集 ID」里，运行即可。

##### 五种「合集从哪来」

| 选项 | 怎么用 | 说明 |
| --- | --- | --- |
| `collection_id` | 填合集 ID，**可一行一个填多个** | **推荐**，最稳，一次就能列出全部章节。填多个会逐个下载，**其中一个失败不影响其它** |
| `article` | 粘一篇合集内的文章链接 | 自动反查它属于哪个合集；反查不到会提示你去拿 ID |
| `author` | 填作者主页，如 `https://xxx.lofter.com/` | 一次把该作者的**全部合集**都下下来 |
| `subscription` | 不用填别的 | 下载**我订阅的全部合集**（需要登录）。已失效的订阅会被跳过并计入统计 |
| `follow_links` | 粘文章链接 | 兜底：顺着文章页里的「上一篇/下一篇」逐篇走。**依赖页面结构，实验性**，抓不到就换上面几种 |

##### 输出结构

```
dir/collection/<合集名>/
├── 001_第一章.txt          ← 按章节顺序，文件名补零便于排序
├── 002_第二章.txt
├── ...
├── images/                 ← 正文里的图片（可以在配置里关掉）
├── <合集名> 目录.txt        ← 章节列表 + 简介 + tag
├── <合集名>.json           ← 原始数据，便于二次处理
└── <合集名> 完整版.txt      ← 可选，全部章节拼成一个文件
```

##### 主要选项

| 选项 | 说明 |
| --- | --- |
| 章节顺序 | 默认「自动（接口顺序）」。发现章节乱了就改成按发布时间正序/倒序 |
| 每个合集最多抓几章 | 0 = 全部。填 3 或 5 可以先用小样本试水。批量时是**每个合集各自**计算的 |
| 保存格式 | `txt`（纯文本，和项目其它任务一致）或 `md`（Markdown，图片用 `![]()`） |
| 下载正文里的图片 | 存到 `images/`，并把正文里的链接换成本地相对路径 |
| **图片并发下载数** | 默认 3，1 = 串行。调太高容易被图床限流，建议不超过 5 |
| **额外导出一本 EPUB** | 需要先 `pip install EbookLib`。没装时这个开关会被跳过并提示 |
| 只保存标题含这个词的章节 | 留空 = 全部。适合只想要其中某几章 |
| **跳过已失效的订阅合集** | 只在「合集从哪来 = 订阅」时有效；失效的仍会记进统计 |
| 已下载的章节跳过 | **断点续传**：中断后重跑只补缺的章节。开了 EPUB 导出时会被忽略（拼书需要完整正文） |
| 另存一个合并的完整版 | 全部章节拼成一个文件，每章前加「第 N 章」 |
| **保存方式** | 「按章节分文件」（默认）或「单个文件」——见下面「保存为单个文件」那一节 |

##### 保存为单个文件（可选）

默认是**按章节分文件**（`001_第一章.txt`、`002_第二章.txt`…）。
想把整本合成一个文件，把「保存方式」改成 **「单个文件」** 即可。

| 怎么启用 | 怎么填 |
| --- | --- |
| 图形界面 | 合集任务 → 参数设置 → 「保存方式」下拉 → 选 **单个文件** |
| 命令行 | `python main.py --task collection --set save_layout=单个文件 --set collection_id=xxx` |
| 配置文件 | `config/settings.json` 里该任务的 `"save_layout": "单个文件"` |

**默认行为**：缺省值是「按章节分文件」，也就是旧版的行为——**不选它就是老样子**，
`dir/collection/<合集名>/` 下仍然是逐章文件 + 目录文件 + JSON。

**单个文件模式下输出什么**：

```
dir/collection/<合集名>/
├── <合集名> 完整版.txt      ← 唯一的正文文件（后缀随「保存格式」，选 md 就是 .md）
└── images/                  ← 只有开启「下载正文里的图片」时才有
```

文件内部的组织顺序是 **合集头信息 → 内联目录 → 各章正文**：

* 头信息：合集名、作者、章节数、tag、合集简介；
* 内联目录：编号 + 章节标题。**故意不做可点击锚点**——Markdown 锚点是按标题 slug 生成的，
  各渲染器规则不一致，生成出来很容易是坏链；编号列表反而稳定；
* 每章：`第 N 章 标题` + 作者 / 发布时间 / 原文链接 + 正文 + tag。

**命名规则**：`<合集名> <合并版文件名><后缀>`

| 合集名 | 合并版文件名 | 保存格式 | 结果 |
| --- | --- | --- | --- |
| 我的连载 | 完整版（默认） | txt | `我的连载 完整版.txt` |
| 我的连载 | 全本 | md | `我的连载 全本.md` |
| 我的连载 | （留空） | txt | `我的连载 完整版.txt` |

合集名与文件名都会过一遍非法字符清洗（`/ \ : * ? " < > |` 等），标题里带奇怪字符也不会写失败。

**开关之间的相互作用**（免得出现「我勾了却没生效」）：

| 其他开关 | 单个文件模式下的行为 |
| --- | --- |
| 生成合集目录文件 | **忽略**——目录已内联进正文，再出一个文件就不叫「单个文件」了 |
| 保存原始 JSON | **忽略**——同上 |
| 另存一个合并的完整版 | **自动生效、无需勾选**（它本来就是你要的那个文件） |
| 已下载的章节跳过 | 改成**整本级**粒度：那个单文件已存在就跳过整本（没有章节文件可以逐章对照） |
| 额外导出一本 EPUB | 仍然生效——EPUB 是你显式要的阅读格式，会与单文件并存 |

**与多文件模式的兼容与切换**：

* 切换只是改配置，**不需要删进度、不需要重下**；
* **切到单文件模式**：之前下载的逐章文件**不会被删除**（不替用户做破坏性决定），
  单文件会从头拼一遍（要拿到完整正文，这一次会重新走一遍章节处理与图片下载）；
* **切回多文件模式**：逐章文件重新生成；如果它们本来就还在，「已下载的章节跳过」会直接命中，
  不会重复下载图片；
* 两种模式下**图片都落在同一个 `images/` 子目录**、命名规则也一致（`003-01.jpg`
  = 第 3 章第 1 张），所以来回切换不会造成图片重复或错位；
* 想要**真·单文件**（连图片都没有外部依赖）就把「下载正文里的图片」关掉——
  图片会以原始链接写进文件，联网可看；想离线带图看书，用「额外导出一本 EPUB」，
  那才是把图文打包进一个文件的正确方式。

**两种模式的章节写法不一样**（这是有意的）：

| | 逐章文件 | 单个文件 / 完整版 |
| --- | --- | --- |
| 章节标题 | `1. 标题`（它是这份文档的标题） | `第 1 章 标题`（书的标题才是大标题） |
| 「合集：…（第 N / M 章）」行 | 有 | 无（同一个文件里冗余） |
| 上一篇 / 下一篇导航 | 有，指向相邻章节文件 | 无（那些链接在单文件里指向不存在的文件） |

##### 为什么不用 Selenium

网上流传的做法（例如 `Lofter_Passage_Get`）是拿 Selenium 打开文章页、点「上一篇」逐篇跳。
本工具**没有沿用那个实现**：那要装 Chrome + ChromeDriver（版本还容易对不上），
而且它没有重试、没有断点续传，中断就得从头来。

这里改走 **App 端接口**：一次请求就能拿到 50 篇的**完整正文 HTML**，
不需要浏览器、不需要逐篇再请求，所以更快、更省流量，断点续传也更好做。
接口地址与参数在 `lofter/appapi.py`，注释里写清了每个坑——尤其是
**不能声明 `Accept-Encoding: br`**（本工具不依赖 brotli，声明了服务端真返回 brotli 就解不出来）。

##### 合集相关常见问题

* **报「没能找出它所属的合集 ID」** → 用 App 分享链接里的 CollectionId，把「合集从哪来」改成 `collection_id`；也可以改成 `author` 直接按作者主页下载他的全部合集；
* **一次想下好几个合集** → 「合集 ID」那个框可以**一行一个**填多个，其中某个失败不影响其它，跑完看底部统计里的「成功合集 / 失败合集」；
* **报证书错误（CERTIFICATE_VERIFY_FAILED）** → 把「校验 SSL 证书」关掉再试；
* **一条都抓不到 / 章节数为 0** → 合集可能被删了或设为私密，先在 App 里确认能打开；
* **章节顺序反了** → 把「章节顺序」改成按发布时间排序；
* **下载太慢** → 调大「图片并发下载数」（默认 3，别超过 5，容易被图床限流）；
* **EPUB 导不出来 / 开关像是没生效** → 先确认装了 `pip install EbookLib`；没装时程序会跳过导出并在日志里提示，其它产物照常保存；
* **订阅模式说订阅是空的** → 订阅接口要 **App 端**的登录信息，PC 网页的 cookie 不通用；
* **同一本合集里少了几章** → 可能是那几章被作者设为私密或已删除，接口拿不到；对照一下 App 里的章节数。

#### 填写登录信息

lofter 现在很多页面都要登录才能看，所以**每个任务都要先填登录信息**，不填都跑不起来。

**三种填法，任选一种**：

| 方式 | 怎么做 | 说明 |
| --- | --- | --- |
| **从浏览器读取**（最省事） | 界面点「登录信息」→ 选个浏览器 → 点「从浏览器读取」 | 需要先执行 `pip install browser-cookie3`。程序**只读本机浏览器里 lofter 的那一条 cookie，不会外传**。注意：**浏览器要完全退出**，否则 cookie 数据库被锁住会读不到 |
| 手工复制 | 界面点「登录信息」自己粘；或命令行走 `python main.py --login` | 就是下面「获取 login_auth 方式1/2」讲的步骤 |
| 自动导入 | 什么都不用做 | 如果你以前填过 `legacy/login_info.py`，首次运行会**自动导入一次** |

命令行也能一步搞定：

```bash
python main.py --login-from-browser                   # 自动挑（会遍历所有浏览器）
python main.py --login-from-browser --browser edge    # 指定浏览器
```

##### 登录方式 和 login_key 对应表

| 登录方式                 | login_key               |
| ------------------------ | :---------------------- |
| lofter id 登录           | Authorization           |

点开 lofter 主页或者喜欢页，按 F12 打开控制台，按 Network，按 XHR，往下划拉几下会加载一个文件（如果加载失败就看下面的方式2），点它

#### l13 保存我的喜欢 & 推荐 & tag

界面任务：**保存喜欢 / 推荐 / tag（PC 端）** ｜ 命令行 id：`like_share_tag`

![InkedQQ截图20200713020059_LI](笔记图/README/InkedQQ截图20200713020059_LI.jpg)

##### 运行模式

共四种运行模式，`like1`, `like2`, `share`, `tag`

`like1` 和 `like2`：保存点过的喜欢，区别是 2 有一个额外的功能

`share`：保存所有点过的推荐

`tag`：保存一个 tag 里的内容（有数量限制，具体看下面的 url）

##### 基本使用

基本使用只要设置三个地方，url，mode，save_mode

![1594540653329](笔记图/README/1594540653329.png)

###### url

`like1`、`like2` 和 `share` 模式的 url 是你个人主页的链接。链接中有的时候有表单，比如 https://ishtartang.lofter.com/?act=qbdashboardlike_20121221_01 ，要把问号和后面的都删掉，变成 https://ishtartang.lofter.com/ 。

tag 模式需要的是 tag 链接，tag 链接有 5 种结尾，分别是 最新(new)、热度总榜(total)、月榜(month)、周榜(week)，日榜(date)，想爬哪个放哪个，浏览器直接点进 tag 的链接是没有结尾的，会指向最新。

tag 链接中有中文复制下来会变成编码，是正常的。

 <img src="%E7%AC%94%E8%AE%B0%E5%9B%BE/README/1658913724972.png" alt="1658913724972" style="zoom: 67%;" />

tag 模式能获取到的条数有限制，new 的上限是 1099，所有热度榜的上限 500。这个限制不是 bug，不是技术问题，是 Lofter 就只让访问这么多，你手动去 web 端翻它也就是显示这么多。

已经找到能获取更多的办法，得用移动端端口，难搞，我自己没这个需求，没程序基础的人弄不到移动端 cookie，所以不打算写。

###### save_mode

界面上是 4 个勾选框（文章 / 文本 / 长文章 / 图片）。

lofter 的博客有 5 种类型，这个爬虫可以爬到文字、图片、长文章。音乐和视频我没想弄。

文字我分类成了有标题的和无标题的，有标题的叫文章，无标题的叫文本。

四个保存项就是「要不要保存这一类」。

保存的图片的命名格式是 "作者名[作者三级域名] 发表时间(编号)"

##### 跑完想重跑怎么办

老脚本跑完会问你 `yes/no`，`yes` 是删掉进度文件、`no` 是退出。

新版本改成了两个开关（都在「输出」分组里）：

* **保存前暂停让我确认自动整理选项** —— 老脚本中间那个强制 `input("ok")`，默认关闭；
* **跑完后自动清空进度文件** —— 老脚本结尾那个 `yes/no`，默认关闭。

也可以直接手动删：`dir/like1_file/` 之类的目录下那些 `.json` 就是进度文件，删掉就从头跑。
命令行还有个快捷方式：`python main.py --task like_share_tag --reset-progress`。

##### 运行过程（这是给我自己的笔记，只是使用的话没必要看）

运行完一个阶段会保存进度，会有文件标识这个阶段已经完成，可以删掉文件来手动调进度。

**阶段1**：获取喜欢/推荐/tag 页面的原始数据，获取完成存到 `blogs_info`，然后从里面解析出需要的数据存到 `format_blogs_info.json`。需要一点时间，8000 多条大概 6 分钟。

`format_blogs_info.json` 文件出现表示阶段1已运行完成。

获取阶段的实际返回条数比请求条数少，因为你点过喜欢/推荐/tag 中曾经存在的内容，有些已经被屏蔽或者作者删除的，也会计算进去，但实际上已经请求不到了，一般来说时间约久消失的条数越多。

**阶段2**：添加自动整理的信息，然后按照 图片、文章、文本、长文章分类，分类完后写到 `classified_blogs_info.json`。大概一两秒。

**阶段3**：对博客进行类型统计和 tag 统计，统计完后输出。很快，一两秒。没有文件，目的是输出。

第三行是字典，每个 tag 具体出现了多少次，第四行是列表。这有个小附加功能，用来辅助生成 `prior_tags`——程序会把所有 tag 按频次写进 `dir/prior_tags.txt`，你从里面挑要用的。

**阶段4**：保存。

保存文章、保存文本、保存长文章很快。这三项没有进度文件，所以保存中断再启动会删掉已经保存的文件重新开始保存。

保存图片能自己记录进度，进度在 `img_save_info.json`，断掉重启会自动读上次的进度。需要的时间比较长，差不多 20-40 分钟 1000 条图片博客。

如果图片存到一半、停止，修改了自动整理选项再启动的话，进度会自己重置到阶段2（这是整个程序唯一自动调进度的地方）。

### 常见问题

#### 依赖装不上

`pip install -r requirements.txt` 报错时：

* **Python 版本太低**：需要 3.10 以上，推荐 3.12；
* **lxml 编译失败**：老版本的 `lxml==4.8.0` 在 3.12 上装不了，本版已经放宽到 `lxml>=5.2.0`，
  如果你是手动装的老版本请升上来；
* 国内网络慢可以加镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

#### 图形界面打不开

* 双击 `run_gui.bat` 一闪而过 → 里面会 `pause`，看一下报什么错；
* 报「没有可用的 tkinter」→ 你装的是精简版 Python，换官方安装包重装（勾选 tcl/tk）；
* 没有任何窗口但进程在跑 → 试试命令行跑 `python main.py --list` 确认环境本身没问题。

#### 怎么确认改动没把老功能搞坏

跑测试：

```bash
python tests/smoke_test.py
```

这是**离线**测试，不需要填登录信息、不会发任何真实请求，40 个用例覆盖了依赖导入、
文件名规则、模板匹配、归档页解析、**合集解析与离线端到端**、**Markdown 链接转义**、
**图片并发次数守恒**、**批量错误隔离**、**EPUB 结构校验**、浏览器 cookie 兜底、
配置读写、断点语义、CLI 参数、图形界面构建与主题切换。
全绿就说明代码本身是健康的（能不能抓到东西还取决于 lofter 的接口，那个只能真跑）。
